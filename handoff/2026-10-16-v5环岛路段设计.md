## 0. 结论先行

**做「三岔环岛」**：待转区选线 → 直行穿岛 / 左绕汇回原主线 / 右绕开新主干道。
**不做闭环环形行驶**——伪 3D 世界模型不允许（见 §1）。

---

## 1. 硬约束：为什么闭环环岛做不出来

本引擎世界模型（`track.js` + `render.js:30-54`）：

- 2600 段 × 5m = 13km 闭环赛道，**z 单调递增**，`s = cam.depth / (z_k − z_cam)`；
- 主线曲率通过 `xAccum` 累积产生弯道视觉：恒定曲率下 `(xAccum − cam.x) ∝ z`，被 `s ∝ 1/z` 抵消 → 屏幕上是**固定的弯向并向远处消失**，路永远不会绕回眼前；
- 匝道是**相对主线的横向偏移带**（`RX = PX[k] + s·off[i]·halfW`），它本身不产生弯道，只能贴在主线旁边。

结论：**「进环 → 绕 300° → 从第 4 个口出来」需要 z 非单调，本引擎做不到**（OutRun 类引擎的固有限制）。
素材库里那张 `road_roundabout_perspective.jpg` 能看到整个环，是因为它是**一次性俯视全路口的静帧**——游戏里没有这种视角。

所以环岛重新定义为**环岛路口**：保留设计稿承诺的全部玩法内核（环形路段 / 内圈慢外圈快 / 选线策略），
把「绕圈」降格为「大曲率绕行匝道 + 中央岛盘」的视觉与手感表达。

> 位置，玩家走「直行」等于从岛盘上碾过去——岛与直行互斥。改为**两出口 + 中央岛**：
> 左绕（汇回原主线）/ 右绕（开新主干道）。见 `线条跑车_当前状态.md`。

长度 1400~1700m，插入 `seq` 序列（替换一个 `jSplit`，保证每圈出现 1 次）。

### 2.1 结构（沿 z 轴）

| 区段 | 长度 | 内容 |
|---|---|---|
| 待转区 | 200m | 车道选向（金箭头），复用现有 `junction` 标记 |
| 让行区 | forkStart−12 / forkStart+4 各一段 | 人行横道 4 条 / 让行三角 2 个，护栏开口 |
| 中央岛盘 | forkStart+2 ~ +36 段（170m） | 三道同心弧 + 3 丛树（岛尖正对分叉口，最宽处落在玩家前方） |

### 2.2 匝道几何

**左绕（汇回型）** —— 与 `jLS` 同构，但中间插入绕岛段并给持续同向曲率：

```
i < rampA(26):        mag = |startOff| + R·(1 − cos(π/2·t1))   0 → R   强制转向（grace 14 段）
rampA ≤ i < +46:      mag = |startOff| + R, cr = dir·ringCurve  绕岛段 自由行驶（见下）
i ≥ +46:              mag = |startOff| + R·cos(π/2·t2)        R → 0   强制转向（grace 8 段）
```
- **左右同用 `CFG.ringDiv = 20`**（原设计左 30 / 右 20 不对称）：真环岛的两条环道是对称的，
  而且 57m 的环道间距会把中央岛推到屏幕最右边——实测完全读不出「旁边有个岛」。
- `ringRampA = 26`（130m，比普通匝道短）：环道只偏 20m，160m 的慢弯会把双车道环道拉成平行长带。
- 绕岛段**双车道**（lanesArr = 2，halfArr = 5.4），供「内圈慢外圈快」取舍。

**绕岛段不进强制转向区**（关键）：强制转向占着 ←/→，而 ←/→ 同时是变道键——绕岛段恰恰是玩家
要选内圈/外圈的地方，强制按住等于把这个选择锁死。这段曲率只有 0.006/段，靠离心漂移自然压弯即可。
（`track.js` 里 `inRingHold` 排除。）

**右绕（分岔型）** —— 与 `jSplit` 同构：

- 收心段 half 5.4→6.35、lanes 2→3，off→0 即成为新主干道（`doneZ` 瞬时切换 + 5s 渐入）

**左右不对称的后果**：左绕 = 汇回原主线（稳，无额外奖励）；右绕 = 不汇回（省掉出口汇流冲突）+ 匝道金币。

> ⚠️ 修订（2026-10-16 实现中）：原设计里的「右绕后决定接哪类路段（城市/沙漠/桥）」**不可行**——
> 13km 循环轨道在开局一次性预生成，段落序列在玩家做出选择之前已固定，无法让后续路段依赖玩家这一把的出口。
> 已改为上述「几何不对称 + 奖励不对称」，视觉与玩法承诺（内圈慢外圈快 / 让行 / 选线）全部保留。

## 4. 玩法

### 4.1 内圈慢外圈快

绕岛段（`brDir≠0` 且 `i ∈ [holdStart, holdEnd)`，即双车道那 230m）：

```js
// track.js · ringLaneAt(zAbs, dir, x)
const off = ramp.off[i];
return Math.sign(off) * (x - off) < 0 ? 'inner' : 'outer';
// main.js：内圈 27.8 m/s (100 km/h)，外圈 41.7 m/s (150 km/h)
```

> 前提修复：原来**所有**匝道上 `laneX = ramp.off`——玩家被钉死在匝道中线上，
> 环道那条车道虚线是纯装饰，「选内圈还是外圈」根本无从选起。
> 现在 `rampInfoAt` 返回 `lanes`，双车道匝道上 `laneX = off + (lane−(lanes−1)/2)·laneWidth`
> 并放开 `laneL/laneR`（单车道匝道偏移为 0，行为不变）。

HUD 一行提示：`内圈 · 限速 100`（白）/ `外圈 · 限速 150`（金）。限速是指数逼近 + 硬钳，
表针稳态正好落在 100/150——只做指数逼近的话油门一直在顶，稳态会停在限速下好几码。

### 4.2 让行

环岛上常驻 4 辆车（两条环道各 2 辆，见 §5）。判定覆盖整条环道匝道（含绕岛段）：

```js
const lead = traffic.ringCarAhead(playerZabs(), p.brDir, p.lane);   // 同车道同环道，90m 内
if (lead) {
  const laneCap = ringLane === 'inner' ? CFG.ringInnerCap
                : ringLane === 'outer' ? CFG.ringOuterCap : CFG.maxSpeed;
  const yCap = Math.min(laneCap, lead.speed + CFG.ringYieldSlack);   // +3 m/s
  p.speed += (yCap - p.speed) * min(1, dt*3);  硬钳到 yCap
}
```

三条设计上的选择，都是被实测推翻后改的：

1. **让行目标是「前车的速度」而不是一个固定低速**。原设计是收到 60 km/h，
   实测把玩家在整段绕岛里钉在爬行速度上——读起来像撞了路障，不像让行。
   跟上前车才是环岛的真实约束（环岛限的是车流，不是礼让线）。
2. **只让同车道的车**。环岛绕岛段是双车道，选了空车道就是「这次不用让」——
   让行因此和 §4.1 的内外圈选择绑在一起，成为一个真正的取舍而不是固定减速带。
3. **`+slack`（比前车快 3 m/s）**：慢慢贴上去超掉它，让行才是一段一段的，
   否则会变成整段绕岛的永久跟车。

HUD：`让行 · 环岛有车`（金色轻微呼吸，不用红——让行是常规路况不是危险）。

### 4.3 奖励

绕岛段金币密度 ×2（每 3 段 1 枚，沿用 `coinRamp`），且**外圈金币 +30**（内圈 3 枚 = 外圈 1 枚 ×3 → 明确引导外圈抢时间 vs 内圈安全的矛盾）。

## 5. traffic.js 改造：环岛车流

环岛车不是「主线车开进环岛」，而是**出生就在环道上的一批车**——环岛的意义就是
「你要往里挤，跟着车流绕一圈」，没有车流的环岛只是一条双车道弯道。

1. **横向位置**：`x = rampInfoAt(z, ringDir).off + (lane − (lanes−1)/2)·laneWidth`，
   相对「环道中线」而不是主线中线；每帧重导（弯出段偏移在变，缓存会漂）。
2. **巡航速度**：按所在圈取限速 × 0.90~0.96（内圈 ~90~96，外圈 ~135~144 km/h），
   加速比减速慢（0.8 vs 3.0），跟车减速后会缓慢重新提速——走走停停的车流而不是滑块。
3. **不进待转区淡出、不跑变道 AI**：环岛车固定绕行路线（`canChange=false`）。
4. **车位按「相对玩家的前距」排**，不是按绕岛段绝对位置铺满：

   ```js
   ringTrafficSlots: [[-1,1,130], [1,0,130], [-1,0,55], [1,1,55]]   // [环道, 车道, 前距m]
   ```

   玩家是全速冲进来的（进绕岛段前 220 km/h）：按绝对位置铺的车在他开到绕岛段之前
   就被全部追过回收了，等真正进环岛只剩一条空路——车流必须跟着玩家往前滚。
   **内圈车放前面、外圈车放它后面**：外圈车限速高，几秒内追上内圈车排队，
   于是「外圈 150」这条卖点经常兑现不了，想抢时间就得盯着队尾空档随时变道
   （绕岛段是可变道的）——这就是让行有牙齿的地方。
5. **维护窗口**：待转区前 `ringTrafficLead`(420m) ~ 驶出环岛后 `ringTrafficTail`(120m)。
   收尾必须按「驶出环岛」算：整条环道 700m，按待转区收尾会在玩家进环岛前就停止补车。
6. **脱环**：驶出环道（`rampInfoAt` 返回 null）时 `ringDir = 0`，交还主线车流逻辑
   （`laneCenterAt` 重导 x、重新参与变道与回收）。
7. **回收**：沿用主线的 `zrel > 820 || zrel < 2`。

### 5.1 渲染层：环岛车不能吃 mainlineAlpha

两个坑叠在一起，症状都是「环岛上没有车」（数据里明明有 4 辆）：

1. `render.js` 里 `a *= mainlineAlpha` 之后才把 `a` 交给 sprite/车流 item，
   绕岛时主线淡出到 0 → 环岛车全部以 alpha 0 画出。现在环岛车取 `aRing`（只吃大气透视）。
2. 更前面一步：`a < 0.015` 时整个主线段被 `continue` 跳过（连 item 收集都不做），
   而岛盘标记只覆盖 34 段，绕岛段其余部分的环岛车根本没进 `items`。
   现在加了一张只装环岛车的段索引表 `traffic.ringBySeg`，跳过判定把它一起放行。

### 7.1 顺带修掉的通用 bug

1. **弯出段末段曲率为 0**（`off[rampA−1] === off[rampA]`，差分为 0）→ 强制转向区提前一段结束，
   完成条按剩余路长算永远攒不满 75% → 必判「转向力度不足」。弯出段越短越明显。
   现在把 `crs[rampA−1]` 接回 `crs[rampA−2]`，转向区恢复连续。
2. **主线淡出把整个世界带黑**（背景/对向车/立柱都乘 `mainlineAlpha`）。新增 `game.bgAlpha`，
   环岛分支恒为 1。
3. **环岛车被主线淡出吃掉**（见 §5.1）：alpha 归零 + 整段跳过，两个坑叠在一起。
4. **`game.jn.phase === 'branch'` 五处全是死代码**：`updateJunction` 只写 `'wait'` / `'bend'`，
   于是「直行通过禁止按左右键」这条 §10.4 规则从来没生效过（AI 也会在直行路口按方向键）。
   改为 `'bend'` 后规则恢复，并按用户规则收窄作用域：
   **只有「这个路口只有一个出口」（`!j.freeChoice`）时乱按左右才判撞毁；有多条路可走时 ←/→ 是合法选道，不罚。**
   实测：不按→通过 / 有岔路按住→通过 / 单出口按住→判「直行通过禁止按左右键」。
   ⚠️ 当前序列里 5 个路口全都有 ≥2 个出口，所以这条规则在现有关卡上是**休眠**的——
   要让它有实际意义需要新增一个单出口路口（设计如此，不是 bug）。
